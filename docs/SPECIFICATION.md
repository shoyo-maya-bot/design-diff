# design-diff 仕様

## 1. Excel 設計書の新旧差分（`design-diff excel`）

### 読み方

| kind | 読むもの | 設定 |
|---|---|---|
| `label` | ラベルのセルから `offset`（既定 `[0, 1]`）離れたセルの値。ラベルが結合セルなら、右・下へは結合範囲の端から数える（2 列に結合したラベルの `[0, 1]` は結合の右隣） | `label`, `offset` |
| `block` | ラベルから `offset`（既定 `[1, 0]`。結合したラベルは結合範囲の下端から数える）の位置から下へ、文章の終わりまでの各行を改行でつないだ文章（ラベルの直下の空行は飛ばし、注記する） | `label`, `offset`, `end_blank_rows` |
| `table` | 見出し行（`header` の列名を含む行、または `title` のラベルの次の行）から、表の終わりまでの表 | `header`, `title`, `key`, `header_rows`, `end_blank_rows` |

- **表・文章の終わり**: 途中の空行は飛ばして（文章では空の行として）読み、次のどれかで終わりとします
  - 空行が `end_blank_rows` 行（既定 2）続いた
  - 行の左端の値が、同じシートの設定にある別の項目のラベル・表題・見出し（`label` / `title` / `header`）
  - 表: 空行の後の、値が 1 セルだけの行（次の節の表題）／ 見出し行と同じ値の行（次の表）
  - 文章: 空行の後の、他の列にも値がある行（次の表）
  - 空行を挟んで読んだときは注記（`note`）を出します。空行で終わりとした下に表の続きらしい行（半分以上の列に値があり、
    1 列目の型が表と同じ）があるときは警告 `table_truncated` を出します（比べていません。`end_blank_rows` を増やしてください）
  - 空行の後の 1 セルだけの行で表を終わりにしたときも `table_truncated` を出します（設定に無い節の表題か、表の続きかを
    区別できないため。次の節なら、その表も設定に書くとラベルとして扱われ警告は出ません）
- **読む範囲**: 値のあるセルだけを走査します（シートの使用範囲全体は走査しない）。1 シートで値のあるセルが 1,000,000 個を超えると、
  超えた行から下を読まずに警告 `sheet_too_large` を出します
- **同じ名前の列**: 見出しが同じ列が 2 列以上あれば、2 列目から `備考#2`・`備考#3` の列名にして両方比べ、警告 `duplicate_column` を出します。
  横に結合した見出しの 2 列目以降は同じ列なので番号を付けません

- 値は計算結果（数式ではなく表示される値）を、**セルの表示形式どおりの文字列**で読みます（devtools-common の `devtools_common.excel.render_value`）。例: 表示形式 `000` の 1 は `001`、`#,##0` の 1500 は `1,500`、`0.0%` の 0.125 は `12.5%`、`yyyy/mm/dd` の日付は `2026/04/05`、`ggge"年"` は `令和8年`。表示形式が「標準」なら `10.0` のような整数の小数は `10`。前後の空白は無視します
  - 文字列で入力した `001` と、表示形式 `000` の数値 1 は同じ値です。値が同じでも表示が変わる表示形式の変更（`000` → `0`）は差分になります
  - 再現できない表示形式（指数・分数・条件付き 等）は書式なしの値で比べます
- 計算結果が保存されていない数式セル（ツールで作った Excel によくあります）は、数式の文字列（例: `=SUM(B4:B5)`）を値として読みます。
  このときはレポートの冒頭に**注意**（JSON では `rule_id` = `formula_cache_missing`、`warning`）を出します。
  Excel で開いて保存し直すと計算結果が保存され、計算結果で比べられます。
  片方のファイルだけ計算結果が無いと、同じ内容でも「計算結果」と「数式」の違いとして差分に出ます。`spec` の Excel も同じ読み方です
- 結合セルは範囲の左上の値として読みます
- 入力の xlsx は開く前に zip の目録で、展開後の合計（512MB）・部品の数（10,000）・部品ごとの圧縮率（1MB を超える部品で 200 倍）の上限を確かめます。
  超えるもの（zip 爆弾の疑い）は開かずに入力の誤り（終了コード 2。`--all` では `pair_failed`）にします。`spec` の Excel も同じです
- 見出しが複数段の表は、各段の見出しを「/」でつないだ列名にします（例: 1 段目「型情報」を 2 列に結合し、2 段目が「型」「桁」なら `型情報/型`・`型情報/桁`）。縦に結合した見出し（例: 2 段ぶんの「項目名」）はそのまま `項目名` です
  - 段数は結合セルから判断します（見出し行の結合セルが次の行まで縦に続き、その行が文字だけ、または横に結合した見出しの下の各列がすべて文字）。最大 3 段です。データ行まで同じように横結合しているだけの表や、結合の下が数値の表は 1 段です（doc-to-markdown と同じ規則。devtools-common の `header_depth`）
  - `header_rows`（1 以上の整数）で段数を指定できます。`header` には 1 段目の列名を書きます。`key` や `spec` の `columns` には「親/子」の列名を書きます
- ラベルの照合では末尾の「:」「：」、空白、セル内改行を無視します
- シートは `name`（ワイルドカード。大文字・小文字を区別し、OS によらず同じ）で選び、新旧をシート名で対応付けます。`pair_by`（正規表現の 1 つ目のグループ）を書くと、その部分で対応付けます。
  同じキーのシートが 2 枚以上あれば最初のシートだけを対応付け、警告 `duplicate_pair_key` を出します

### 差分の種類

| category | 表示名 | 補足 |
|---|---|---|
| `sheet_added` / `sheet_removed` | 追加・削除されたシート | |
| `sheet_renamed` | シート名の変更 | `pair_by` で対応付けたとき |
| `value_changed` | 値の変更 | label / block |
| `label_added` / `label_removed` | 追加・削除された項目 | 片方にだけラベルがある |
| `label_not_found` | どちらにも無いラベル | **設定の見直しが必要** |
| `table_added` / `table_removed` | 追加・削除された表 | 片方にだけ表がある（改訂で表を足した・消した）。設定の誤りではないので、`--fail-on-diff` なしなら終了コード 0 |
| `table_not_found` | どちらにも無い表 | **設定の見直しが必要**（`title`・`header` が設計書と合っていない） |
| `column_added` / `column_removed` | 追加・削除された列 | |
| `key_column_missing` | キー列が無い | **設定の見直しが必要**（行の比較はしない） |
| `duplicate_key` | キーの重複 | **設定の見直しが必要**。重複した行も同じキーの中の出現順で対応付けて比べる（2 件目は「キー（2 件目）」） |
| `row_added` / `row_removed` | 追加・削除された行 | 行の内容を「列=値」で要約 |
| `cell_changed` | セルの変更 | 「キー の 列名」で場所を示す |
| `outside_changed` | 比較対象外のセルの変更 | 設定のどの項目でも読まなかったセル（承認者欄・表紙など）の変更の件数と場所（シートごと。先頭 10 か所）。`--outside summary`（既定） |
| `outside_cell_changed` | 比較対象外のセルの変更 | 同じものを 1 セルずつ（項目 = セル番地）。`--outside all` |

読み方の警告（レポートの冒頭の**注意**。JSON では warning）: `formula_cache_missing`（数式の計算結果が無い）、
`duplicate_column`（同じ名前の列）、`table_truncated`（表の続きらしい行を比べていない）、
`duplicate_pair_key`（`pair_by` のキーが重複したシート）、`sheet_too_large`（値のあるセルが上限を超え、一部の行だけ読んだ）、
`blank_key`（表のキー列が空の行。対応付けられないので比べていない。変更前・変更後ごとに件数と行番号（先頭 10 行）を出す）。

- **キー列が空の行**: `key` の列がすべて空の行は、新旧で対応付けられないため比べません（差分にも出ません）。そのような行があれば
  警告 `blank_key` に、変更前・変更後のどちらか、表の名前、行数、シートの行番号を出します。キーを埋めるか、`key` を見直してください

### 設定に無いセルの比較

設定の項目（label / block / table）で読んだセル以外の、値のあるセルを比べます。表（table）で読んだことになるのは、見出しから最後の行までの、表の列の範囲（見出しのある左端の列〜右端の列。横に結合した見出しはその右端まで）のセルです。同じ行でも表の列の範囲の外のセル（表の右のメモ・確認欄など）は、設定に無いセルとして比べます。設定のどのシートにも当たらないシート（表紙など）は、
シート名で新旧を対応付けて全部のセルを比べます。行は内容で対応付ける（difflib）ので、表の行が増えて下の承認者欄がずれただけなら差分にしません。
セル番地は変更後の位置（削除された行は変更前の位置）です。`--outside off` で比べません。

「設定の見直しが必要」な差分が 1 件でもあると終了コード 1 です（差分を取り違えたまま「変更なし」と判断しないため）。

### 比べないもの

書式（色・罫線・フォント）、図形・画像、コメント、非表示の状態、印刷設定、数式そのもの（計算結果が保存されていないセルを除く）。
文章やコメントまで含めて見たいときは doc-to-markdown で Markdown にしてから `git diff` してください。

## 2. API 定義書と OpenAPI の整合（`design-diff spec`）

両方を次の形にそろえてから比べます。

```text
API ID → method, path, request{項目名: type, required, max_length, location}, response{…}, statuses[]
```

- 設計書: `sheets`（ワイルドカード。大文字・小文字を区別）に合うシートを 1 API とし、`api_id` のラベルの値を API ID にします
- OpenAPI: `x-api-id` → `operationId` → `"METHOD path"` の順で API ID にします。
  操作は `get` `post` `put` `patch` `delete` `head` `options` `trace` を読みます。
  path / query / header のパラメータと JSON の requestBody を request、2xx 応答のうち JSON のスキーマを持つ最初のもの（`200` → `201` → … → `2XX` の順。書いた順ではない）を response とします。
  本文の無い `202` / `204` が先に書いてあっても、本文のある `200` で比べます。本文のある 2xx が複数あれば、どれで比べたかを注記します。
  入れ子のオブジェクトは `親.子` の項目名にします。応答・要求の本体そのものが配列なら要素の項目を読みます。
  項目が object の配列なら、配列の項目（型 `array`）と要素の項目を `親.子` で持ちます（`orders: [{id}]` → `orders` と `orders.id`。配列の配列も同じ）。
  文字列などの配列は要素の項目を作らず、配列の項目の桁に要素の `maxLength` を使います。`$ref` はファイル内のものだけ解決します
- 応答ステータスは `responses` のキー（`200`・`404` など）です。`default` は特定のステータスではないので比べず、あることを注記します
- OpenAPI のスキーマの組み合わせは次のように読みます
  - `allOf`: 全部の `properties` と `required` をつないで 1 つのスキーマにします（`$ref` や入れ子の `allOf` も展開します）。
    親の `required` は `allOf` の中で定義された項目にも効きます
  - `oneOf` / `anyOf`: 全候補の項目を合わせて（和集合で）比べます。必須は「全候補で必須なら必須、どの候補でも任意なら任意」、
    候補によって違う項目は必須を比べません。どの候補がどの項目を持つかと、候補があることをレポートの冒頭に注記（`info`）するので、人が確認してください。
    設計書に無い候補の項目（`field_missing_in_doc`）は、右の列に「oneOf 候補2」のようにどの候補の項目かを出します
  - `oneOf: [X, {type: "null"}]` のような null を許すだけの書き方と、OpenAPI 3.1 の `type: [string, "null"]` は、null でない方の型として読みます（注記は出しません）。
    候補で型が違う項目（例: `anyOf: [string, integer]`）は型を比べません
  - `discriminator`: 候補の選び分けには使いません（`mapping` も読みません）。判別用の項目名を注記に添えるだけで、その項目自体は各候補の `properties` から読みます
  - 自分自身を参照するスキーマ（木構造など）は、2 回目に出てきたところで展開をやめ、注記します
- 要求・応答の本体は JSON のメディアタイプから読みます: `application/json`（`; charset=utf-8` などパラメーター付き・大文字小文字を問わない）、`*+json`（`application/problem+json` など）、`*/*` の順に、最初にスキーマのあるもの。JSON の無い本体（`application/xml` だけなど）は比べません
- パスは `{…}` の名前の違いと末尾の `/` を無視して比べます
- 型（`type`）と受け渡し位置（`location`）は大文字・小文字と前後の空白を区別せずに比べます（`String` と `string`、`Query` と `query` は同じ）

| category | 表示名 |
|---|---|
| `api_missing_in_oas` / `api_missing_in_doc` | 片方にしか無い API |
| `method_mismatch` / `path_mismatch` | メソッド・パスの不一致 |
| `field_missing_in_oas` / `field_missing_in_doc` | 片方にしか無い項目 |
| `type_mismatch` | 型の不一致（設計書の型は `type_map` で変換） |
| `required_mismatch` | 必須の不一致（`required_marks` のどれかなら必須） |
| `length_mismatch` | 桁の不一致（設計書に桁があるときだけ。桁は表示形式に関係なくセルの値で読み、文字列の `1,000` や全角も数値として読む。数値として読めない桁は比べず、警告 `not_a_number`） |
| `location_mismatch` | 受け渡し位置の不一致（設計書に位置があるときだけ） |
| `status_missing_in_oas` / `status_missing_in_doc` | 片方にしか無い応答ステータス（設計書に応答の表があるときだけ） |

読み飛ばしたシート（API ID が無い）、OpenAPI の `oneOf` / `anyOf` や循環参照は、レポートの冒頭に注記します。

同じ API ID のシートが 2 枚以上あるときは、**最初のシート**だけを比べ、警告 `duplicate_api_id`（どのシートかを列挙）を出します（新旧比較の `pair_by` の `duplicate_pair_key` と同じ扱い）。
OpenAPI 側で同じ API ID（`x-api-id` → `operationId`）の操作が 2 つ以上あるときも、**最初の操作**（ファイルの出現順）だけを比べ、警告 `duplicate_api_id`（どの操作かを `METHOD path` で列挙）を出します。

項目は**名前と受け渡し位置**（`location`: path / query / header / body）で識別します。

- 同じ名前で位置が違う項目（path パラメーターの `id` と body の `id` など）は別の項目として読み、位置の同じもの同士を比べます。レポートの項目名は `id（path）` のように位置を添えます
- 名前が両側で 1 つずつなら、位置が違っても同じ項目として対応付け、`location_mismatch` を出します
- 同じ名前・同じ位置の項目が 2 つ以上あるときは、後のもので上書きします
- パス共通の `parameters`（Path Item に書いたもの）は、各操作の `parameters` と合わせて読みます。同じ `name` と `in` のパラメーターが両方にあれば、**操作のもの**を使います（OpenAPI の規則）。
  header の名前は大文字・小文字を区別しません（`X-Request-Id` と `x-request-id` は同じ）。Path Item 自体が `$ref` でも読みます。`parameters` が配列でない・`name` の無い要素は構造の誤り（終了コード 2）です

OpenAPI の YAML / JSON の構文の誤り、`paths` や操作・パラメーターが辞書でないなどの構造の誤り、ファイル内に無い `$ref` は、入力の誤り（終了コード 2）です。
`spec` の設定（`config/spec.yaml`）は読み始める前に形を確かめ、`api_id`・`method`・`path` の `label` が無い、`offset` が整数 2 つでない、
`request`・`response` に `columns.name` が無い、`statuses` に `column` が無い、`type_map` が辞書でないなどは設定の誤り（終了コード 2。どの項目かを表示）です。
それ以外の想定外の例外は、設定や入力の誤りとはみなさず内部エラー（終了コード 3）にします。

## 3. 出力

- Markdown: 種類ごとの件数の表と、種類ごとの「場所 / 項目 / 左 / 右」の表。左は変更前（または設計書）、右は変更後（または OpenAPI）。セルの値・注意・注記の `&` `<` `>` は `&amp;` `&lt;` `&gt;` に、表のセルの `\` `|` は `\\` `\|` に、改行は `<br>` にします（値の HTML がそのまま解釈されたり、列がずれたりしないように）
- JSON など: devtools-common の共通レポート形式。`rule_id` = category、`expected` = 左、`actual` = 右。
  設定の見直しが必要な差分は `error`、それ以外の差分と注意（`formula_cache_missing`）は `warning`、注記は `info`
- `excel --all` の一覧: ペアごとに `pair_compared`（`info`。差分の件数と出力先）、ファイルが無い `pair_missing`・読めない `pair_failed`（`error`）
